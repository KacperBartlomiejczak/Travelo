- Tables & RLS policies (`trips`, `trip_members`, `flight_segments`, `to authenticated`, `(select auth.uid())`): owner — select / insert / update / delete on `trips` (`owner_id`), and on `trip_members` / `flight_segments` via `private.is_trip_owner(trip_id)`; linked member (`trip_members.user_id`) — select only via `private.is_trip_viewer(trip_id)`. The helpers are `security definer`, `search_path = ''`, in the non-exposed `private` schema, executable only by `authenticated`. Grants: `authenticated` select / insert / update / delete, `service_role` all, nothing for `anon`.
- `trip_photos` RLS: select = owner or linked member; insert / delete = owner; no update policy. Grants: `authenticated` select / insert / delete, `service_role` all, nothing for `anon`.
- `profiles` RLS (`to authenticated`):
  - select / insert / update only the own row (`id = (select auth.uid())`);
  - insert also requires a non-anonymous user (the `is_anonymous` claim);
  - no delete.
  - Grants: `authenticated` select, insert `(id, username, interests, avatar_id)`, update `(username, interests, avatar_id)`; nothing for `anon`.
- Storage policies for the bucket `avatars`: insert / select / update / delete only inside your own `<userId>/` folder.
- Storage policies on `storage.objects` (bucket `trip-photos`, `to authenticated`):
  - insert: your own `owner_id`, into a trip you own (the trip comes from the path);
  - select: your own files, or files of a trip you are linked to;
  - update: your own files, and only inside a trip you own;
  - delete: your own files. This lets the organizer clean up even after the trip is gone.
- RPC: `public.create_trip(trip jsonb, members jsonb, segments jsonb)` — `security invoker` (RLS applies), inserts the three in one transaction with `on conflict (id) do nothing` (idempotent), owner always the caller; members always with `user_id` null, then every member with a `friend_code` is linked through `private.link_trip_member` (friend-invite 2b). Errors: `FI001` own code, `FI002` unknown code, `23505` same friend twice; each rolls back the whole call. A retry never re-points a link. Executable by `authenticated`, `service_role`. Reads `daily_budget_minor` for the trip and every member.
- RPC: `public.set_trip_budget(trip_id uuid, organizer_daily_minor bigint, members jsonb, updated_at timestamptz)` — `security definer`, `search_path = ''`, owner checked with `private.is_trip_owner`; updates the trip and the listed members in one transaction, last write wins on `budget_updated_at` (older or equal = silent no-op). Errors: `42501` not the owner / no such trip, `22023` a member outside the trip. Executable by `authenticated`, `service_role` (daily-budget step 2). `trip_members.daily_budget_minor` is not in the column update grant, so only this RPC changes friends' amounts.
- Friend invite (`20261020120000_friend_invite.sql`, `20261020130000_friend_invite_code_only.sql`; `security definer`, `search_path = ''`):
  - `public.find_profile_by_friend_code(code text)` → `(username, interests)` of the one profile with exactly that code; nothing without `auth.uid()` or for an anonymous JWT; `authenticated` + `service_role` only.
  - `public.trip_organizer_username(trip_id uuid)` → the owner's nick for the owner or a linked member, else null (no existence oracle).
  - `private.link_trip_member(member_id uuid, code text)` (not API-exposed): the caller must own the member's trip (`42501`), resolves the code (`FI002` unknown, `FI001` own), sets `user_id` only where it is null.

## Data and security rules
- Money is stored as **integer minor units + ISO 4217 currency code**. No floats for money, ever.
- Timestamps are ISO 8601 with offset; flights also store the airport's IANA timezone.
- **RLS on every table.** A trip is visible only to its owner and to members with a linked `userId`. Linked members are read-only, except their own expenses (`prompts/expenses/plan.md` D15).
- Store only `placeId` long-term from Google Places (respect their terms); fetch details live.
