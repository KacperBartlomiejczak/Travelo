# Edit and delete a trip

Entry: the ⋮ button on the home screen, owner only (`TripMenuSheet`: "Name and photo", "Change budget", "Delete trip"). Renaming, the cover and deleting need internet; "Change budget" works offline (see [trip-budget.md](trip-budget.md)). Offline, the other two rows are disabled with the hint "You need internet to rename or delete the trip."

- **Sheets:** `TripDetailsSheet` ("Name and photo", "Save", error "Couldn't save. Try again."; its cover picker gets `trip.coverUrls`, see [trip-cover.md](trip-cover.md)). `DeleteTripSheet` (title "Delete trip “{{name}}”?", "Flights, members, budget and photos will be gone. This can't be undone.", "Delete trip" / "Cancel", error "Couldn't delete the trip. Try again."; both buttons are disabled while pending). Hooks: `useUpdateTripDetails`, `useDeleteTrip` (cancels running trip reads on mutate, resets the current trip, invalidates the list).

- **Rename / cover** (`updateDetails`): parse `TripDetailsInputSchema` (name trimmed, 1–60, cover required) → `ensureSession` → read the stored cover (gone → `trip-not-found`) → a `photo:` value that is not the stored cover rejects `cover-not-current`; a `file://` choice is prepared (`preparePhoto`) and uploaded (thumbnail, then file, `upsert: false`) → `trips.update({ name, cover_image_uri })` `.eq('id', …).select('id')`; 0 rows → `trip-not-found`; unreachable → `ServerUnreachableError`; a failed upload or update rejects and removes the new files, except when the update is unreachable: it may have been applied, so the new files are kept (left-overs go with the trip folder). After a success that replaced a `photo:` cover, the old two files are removed (best effort). Online only; the UI disables it offline.
- **Delete** (`delete`): `ensureSession` → the trip's Storage folder is listed (pages of 1000) and its files removed (chunks of ≤ 1000) **before** the row; any error rejects and keeps the trip and its copies (P7) → `trips.delete().eq('id', …).select('id')` (members, segments, trip photos, expenses and trip plans go by cascade). 0 rows → a read of the trip tells "already gone" (success, D13) from "still visible, not deletable" (`trip-not-deletable`, copies kept). On success `LocalStore.forgetTrip` removes the trip's copy, the choice of it, its pending budget change, its photo-list copy, its expenses and its list entry in one SQLite transaction. The hook then resets the current-trip query, so the home screen shows the default trip or the empty state. Online only. After the row is gone, the folder is checked once more, best effort.
