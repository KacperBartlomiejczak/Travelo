# Ticket import

Entry: "Import ticket" on the wizard's flights step (`/trips/new`) opens `TicketImportSheet` with two choices. Nothing is saved automatically: the data goes into the wizard draft and the organizer checks it before "Next". Plan and decisions: `prompts/ticket-import-ai/plan.md` (D1–D13, Z1–Z9).

- **From a file** (needs internet; disabled offline with a hint): the consent text and a checkbox every time (D2 — also after an error; nothing is remembered), a PDF / Photo switch, "Send". `ticket-pick.ts`: a PDF via `expo-document-picker`, a photo from the gallery only (Z1), resized to JPEG with the longer side ≤ 2000 px; both checked with `sniffTicketFile` (magic bytes, ≤ 5 MB); the app's temp copy is deleted after reading (D5). `useExtractTicket` (mutation, no retry) → `extractTicket` (`src/data/ticket-import.ts`, 45 s timeout in `fetch-timeout.ts`) → Edge Function `extract-ticket` (see `backend.md`). The sheet cannot be closed while sending.
  - **Server cascade:** stage 1 without AI (barcode → BCBP, PDF text → regexes); complete → done, no quota (a PDF with more pages than stage 1 reads, 3, is never complete here). Otherwise Gemini fills only what is missing (5 per day); the stage-1 fields are certain and Gemini must agree with them.
  - **Result:** a non-empty form first asks "Replace the flights you entered?" (D3); then `draftFromTicket` replaces both directions; snackbar "check them" (complete) or "fill in the times" (partial, Z8). Not a ticket → a centred message; it does not use one of the 5 daily AI imports (D6), but it counts toward the daily limit of 10 rejected files (D7). Limit, unsupported or too large file, unreachable, other errors → a message with "Try again" (the consent is cleared).
- **Scan a boarding pass** (works offline, nothing leaves the phone): `BoardingPassScanner` — a full-screen camera (`expo-camera`, PDF417 / Aztec / QR), permission request and a denied state with "Open settings". A code → `parseBcbp` with the phone's local date (the year is the nearest occurrence of the day, Z3) → "Which flight should it go to?" (outbound / return, Z2) → `withBoardingPass` adds the legs to that direction (a lone empty card is replaced); times stay empty and the day is suggested. An unrecognised code shows a message and scanning continues. The passenger name and booking reference are dropped in the parser (Z5).
- **Privacy:** privacy policy section 2.8 and terms 6.6 (`docs/legal/`).
