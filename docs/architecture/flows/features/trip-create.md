# Create a trip

Entry: the 4-step wizard at `/trips/new` (flights → friends → budget → summary). Needs internet.

- **Create:** parse `CreateTripInputSchema` → `ensureSession` (the stored user id; `NotSignedInError` without a session — it never signs in) → `buildTrip` (client UUIDs from `expo-crypto`, times as ISO with offset, `ownerId` = the user id, `budgetUpdatedAt = createdAt`; members keep `userId: null`, the friend codes travel in `CreatedTrip.friendCodes`, member id → code) → `toCreateTripArgs` (members parsed with `CreateTripMemberPayloadSchema`: `friend_code`, never `user_id`) → `rpc('create_trip')`, then the new trip becomes the chosen trip (SQLite). `FI001` → `OwnFriendCodeError`, `FI002` → `UnknownFriendCodeError`, `23505` on `trip_members_trip_user_key` → `FriendAlreadyAddedError`; any other error rejects as before; nothing is queued (creating needs internet).
- **Create with a gallery cover** (trip-covers Q1): the trip is created on `DEFAULT_COVER` (Storage rules need the trip), then the photo is prepared, uploaded and the trip updated to `photo:<uuid>`. Any failure there keeps the default, removes what was uploaded (kept when the update is unreachable, as in `updateDetails`) and still resolves; the caller tells it by "asked `file://`, got a preset". The summary then closes the wizard with `coverUploadFailed=1`, and `HomeScreen` shows its snackbar „Nie udało się wysłać zdjęcia okładki. Zmień je w „Nazwa i zdjęcie”.” once and clears the param (`navigation.setParams`).
- Create-trip wizard, friends step (friend-invite): each `FriendCard` has an optional friend code. `friendCodeStatus` (`src/features/trip-create/friend-code.ts`, pure) decides on the phone first (offline, empty, incomplete, impossible code, own code from `useMyProfile`, a code already in another card), then one `useFriendLookup` request after the 6th character. A found code fills the card with the nick and interests (read-only) and sets `friendCode`; editing it gives back an empty manual card (D9). The typed text (`codeText`) is UI state only and is never sent. "Dalej" is blocked while any code is unresolved (D13).
- Create-trip wizard: the draft lives in `TripDraftProvider` (wizard layout) as airport-local strings and typed text; each step validates its slice with its Zod schema on "Next"; the summary validates the name with `TripDetailsInputSchema` and saves `toCreateTripInput(draft)`. The name follows the flights (`defaultTripName`) until the organizer types one; the cover starts on `DEFAULT_COVER` and is a preset or a gallery photo (`CoverChoice`). Leaving with unsaved input is blocked by `usePreventRemove`: `LeaveGuard` keeps the blocked navigation action in state and shows the in-app `ConfirmDialog` („Zostań” / „Odrzuć”); „Odrzuć” dispatches the stored action, anything else drops it. A second attempt while the dialog is open keeps the first action. After saving there is no dialog.
