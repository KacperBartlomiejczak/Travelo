# Friend invite (friend code)

Entry: the friends step of the create-trip wizard.

- **Friend lookup** (friend-invite, `ProfileRepository.findByFriendCode`): `FriendCodeInputSchema` first (an invalid code rejects with `ZodError` before any request) → `signedIn()` → `rpc('find_profile_by_friend_code', { code })` → `FoundFriendSchema.array().max(1)` → the friend or `null`. Unreachable → `ServerUnreachableError`. `useFriendLookup(code)` (query key `['friend-lookup', code]`, `retry: false`, `gcTime: 0`, `networkMode: 'always'`, `refetchOnWindowFocus: false`, `refetchOnReconnect: false`) asks once per code.
- **Code format:** 6 characters from an alphabet without `0`, `O`, `1`, `I` and `L` (`src/schemas/profile.ts`).
- **Card status** (`friendCodeStatus`, `src/features/trip-create/friend-code.ts`, pure), in this order: linked → offline → empty → incomplete → unknown → own → duplicate → checking → the lookup result. Only `checking` calls the server. Messages on the card (`FriendCard`): "Checking the code…", "The code has 6 characters.", "That's your code.", "This friend is already added.", "No user has this code.", "Connect to the internet to check the code.", "Couldn't check the code. Try again." A linked card has its name and interests locked.
- **Draft rules** (`draft.ts`): a found code fills the card (`withFoundFriend`); editing a found code gives back an empty manual card (`withCodeText`); `hasUnresolvedCode` blocks "Next" on the friends step. The own code comes from `useMyProfile`; codes already on other cards are compared on the friends screen. Only `friendCode` is sent to the server, never `codeText`. Server errors map from `FI001`, `FI002` and `23505` (see [trip-create.md](trip-create.md)).
- **Linked member's view** (`CurrentTrip`): the trip is read-only (no ⋮ menu, read-only photo strip, hidden when empty), the viewer's own row is hidden in Travellers, and an organizer line reads "{{name}} (organizer)" or "Organizer"; the organizer's nick comes from `trip_organizer_username`.
