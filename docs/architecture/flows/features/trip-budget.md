# Trip budget (works offline)

Entry: the Budget card on the home screen („Zmień”) and the trip menu. Offline write, like expenses.

- Model (daily-budget B1–B8): every traveller has a **daily** budget — the organizer's on the trip (`dailyBudget`), each friend's on the member (`dailyBudgetMinor`). The sheet (`BudgetSheet`) and the wizard's budget step have a „Razem / Osobno” switch (only with friends): Razem = one daily amount for everyone, Osobno = an amount per person. The mode is not stored: the sheet opens in Razem when all amounts are equal (A1). Switching (Q1, Q6): Osobno → Razem shows the organizer's amount; Razem → Osobno keeps each friend's amount, and an empty one gets the shared amount; typing an amount in Razem sets it for everyone. The sheet keeps the Osobno amounts only while it is open. Totals for the trip = daily × trip days, so changing the dates changes the totals, not the daily amounts (B3). The home card shows the daily amount (or the group's sum per day when amounts differ) and the trip total ("Razem … na podróż" for a group, "… na podróż" for a solo trip, Q5).
- Offline budget: `setBudget(trip, { organizerDailyMinor, members })` validates with `TripBudgetChangeSchema` (base currency, amounts > 0; members not listed keep their amount) and upserts one `pending` row in `trip_budget_changes` (members in `members_json`, no network). `syncBudgets()` (serialized: one run at a time) sends each change with `rpc('set_trip_budget')` (owner only, trip + members in one transaction, last write wins by `budget_updated_at`; an older change is a silent no-op = synced). Unreachable (status 0) → stays `pending` with the attempt counted; refused (e.g. 42501 not the owner / no such trip, 22023 a member outside the trip) → `failed` with its error. A synced change is written into the SQLite copy of that trip, then removed. It returns `nextAttemptAt` (backoff 1 s × 2ⁿ, max 5 min). `BudgetSyncProvider` runs it on start and whenever the network comes back (`expo-network`), on app foreground, after each save, and at `nextAttemptAt`; afterwards it cancels any in-flight trips read and refetches `['trips']`.
