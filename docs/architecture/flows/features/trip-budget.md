# Trip budget (works offline)

Entry: the Budget card on the home screen ("Change", accessibility label "Change budget"; owner only) and the trip menu. Offline write, like expenses.

- Model (daily-budget B1–B8): every traveller has a **daily** budget — the organizer's on the trip (`dailyBudget`), each friend's on the member (`dailyBudgetMinor`). The sheet (`BudgetSheet`) and the wizard's budget step have a "Together" / "Separately" switch (only with friends, under the label "Group budget"): Together = one daily amount for everyone, Separately = an amount per person. The mode is not stored: the sheet opens in Together when all amounts are equal (A1). Switching (Q1, Q6): Separately → Together shows the organizer's amount; Together → Separately keeps each friend's amount, and an empty one gets the shared amount; typing an amount in Together sets it for everyone. The sheet keeps the Separately amounts only while it is open. The trip total is the sum of every traveller's daily amount × trip days, so changing the dates changes the totals, not the daily amounts (B3). The home card shows the daily amount (or "per day for the group" when amounts differ) and the trip total ("Total {{total}} for the trip" for a group, "{{total}} for the trip" for a solo trip, Q5). The sheet has "Save" and the error "Couldn't save this. Try again."; it closes on success, and a failed sync is retried from `SyncIndicator`.
- Offline budget: `setBudget(trip, { organizerDailyMinor, members })` validates with `TripBudgetChangeSchema` (base currency, amounts > 0; members not listed keep their amount) and upserts one `pending` row in `trip_budget_changes` (members in `members_json`, no network). `syncBudgets()` (serialized: one run at a time) sends each change with `rpc('set_trip_budget')` (owner only, trip + members in one transaction, last write wins by `budget_updated_at`; an older change is a silent no-op = synced). Unreachable (status 0) → stays `pending` with the attempt counted; refused (e.g. 42501 not the owner / no such trip, 22023 a member outside the trip) → `failed` with its error. A synced change is written into the SQLite copy of that trip, then removed. It returns `nextAttemptAt` (backoff 1 s × 2ⁿ, max 5 min). `BudgetSyncProvider` runs it on start and whenever the network comes back (`expo-network`), on app foreground, after each save, and at `nextAttemptAt`; afterwards it cancels any in-flight trips read, refetches `['trips']`, invalidates `['expenses']` and runs the expense sync. Connectivity that is still unknown counts as online (`useIsOffline`). `hasUnsentChanges` drives the sign-out warning in Settings.
