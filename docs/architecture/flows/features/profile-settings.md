# Settings, edit profile, avatar, delete account

Entry: the gear on the "Profile" tab (`/settings`) and the profile photo (`/avatar`, or the gallery when there is no photo). Screens: `/settings`, `/edit-profile`, `/avatar` in [frontend.md](../../frontend.md).

- **Settings layout** (`prompts/settings-redesign/plan.md`): the e-mail under the nick comes from `useAccountEmail` → `useSession().email()` → `SessionSource.email()`, which reads the stored Supabase session (`auth.getSession()`, works offline) through `EmailSchema`; no session, an anonymous session, a read error or an invalid address → `null` and no e-mail line. The PRO banner ("Go PRO") shows only without PRO and opens the RevenueCat paywall; PRO users get a "Subscription" row instead (Customer Center). Both are disabled offline and until the PRO identity is confirmed (`useIsProIdentityConfirmed()`). See [subscription.md](subscription.md).
- **Other Settings rows** (`SettingsScreen.tsx`): "Privacy policy" and "Terms of use" push `/legal/privacy` and `/legal/terms` (not offline-gated, see [legal-pages.md](legal-pages.md)); a "Version" row; the identity block shows skeletons while loading and no e-mail line when the e-mail is `null`; offline, a banner says "You're offline. Account settings need internet."
- **Theme and language:** rows on Settings open a `BottomSheet`; `usePreferences` reads and writes `preferences` (`src/data/preferences.ts`, `expo-sqlite/kv-store`, a separate database that `clearUserData` does not touch), so both stay on the phone after sign-out (D8). The same store keeps the home budget chart style (`preference.chartStyle`: `line` default / `bar` / `donut`, unknown value or failed read = `line`; trip-spend-chart), picked on the „Wykres budżetu” row between Motyw and Język. They are applied at startup: the theme through `Appearance.setColorScheme` (`applyThemePreference`), and the language through `resolveLanguage`. Works offline. The sheets offer System / Light / Dark and System / Polish / English.
- **Edit profile:** `useUpdateProfile` → `ProfileRepository.updateProfile` (Supabase, then the profile copy in SQLite). Input is `ProfileEditInputSchema`. A taken nick returns `UsernameTakenError`. Server-first: saving is disabled offline and while nothing has changed, and the offline banner there says editing needs internet (`settings.editProfileOffline` via `AuthFormScreen`'s `offlineText`, D21) instead of the default "You're offline. Changes will sync when you're connected." text.
- **Avatar:** `usePickAvatar` (gallery, square crop) → `useChangeAvatar` / `useRemoveAvatar` → `ProfileRepository.changeAvatar` / `removeAvatar` (private `avatars` bucket). Server-first.
- **Sign out:** `SettingsScreen` → `ConfirmDialog`, with a warning when budget changes have not been sent yet → `useSignOut` → `useSession().signOut`. Disabled offline ("Connect to the internet to sign out.") and while a check or sign-out is pending. The dialog reads "Sign out?" / "You will be signed out on this phone.", with "Unsent budget changes will be lost." added when changes are unsent.
- **Delete account:** disabled offline or without a loaded profile. `DeleteAccountDialog` ("Delete account?", the own nick must match; a mismatch clears the field) → `useDeleteAccount` → `ProfileRepository.deleteAccount` → Edge Function `delete-account` (see [backend.md](../../backend.md)). The function removes the owned trips' photos, then the avatar, then the auth user; the database cascades the rest. A linked friend's member row and expenses stay (D11). After success, `Session.signOutAfterDelete` clears the phone (`clearUserDataOnPhone`: image caches, `Paths.cache`, SQLite) and `WelcomeScreen` shows the goodbye message "Account deleted." while `Session.accountDeleted` is true. A wrong nick returns `UsernameMismatchError`.
