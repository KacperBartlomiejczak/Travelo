# AI trip plan

Entry: the „Plan” side of the Plan tab's „Plan” / „Odkryj” switch, shown only with a current trip (`TripPlanSide` in `src/features/plan/`). Needs internet: offline the screen shows the banner, „Plan wymaga internetu.” and a disabled „Ułóż plan z AI”; a saved plan is not shown offline (its names come from Google at view time).

Plan and decisions: `prompts/ai-trip-plan/plan.md` (D1–D19).

- **Read** (`useTripPlan` → `fetchAppTripPlan`, `src/data/trip-plan.ts`): `trip_plans` row by trip id (RLS: owner or linked member), parsed with `TripPlanSchema`; none → empty state. Memory-only query, no retry.
  - Names, addresses and Maps links: `usePlaceDetails` → `fetchAppPlaceDetails` → `place-details` Edge Function in chunks of ≤ 40 ids, merged into a map; memory only (Google allows storing only `placeId`, D14). A failed lookup shows an error with retry.
- **Empty:** the owner sees „Nie masz jeszcze planu podróży” and „Ułóż plan z AI”; a linked friend sees „Organizator nie ułożył jeszcze planu.” without a button.
- **Question cards** (`PlanWizard`): „Gdzie zwiedzamy?” (only the destination / other cities too) → „W jakim promieniu szukać?” 50/100/200/300 km (only for other cities) → own cities (optional, ≤ 2, from the airport list, sent as IATA codes; not the destination, no duplicates) → preference chips (optional: relaxed / intense pace — exclusive —, lots of food, no museums). Cards slide (Reanimated `SlideInRight` / `SlideOutLeft`, reversed going back, `motion.duration.emphasis`); with reduced motion they cross-fade in 80 ms. The request is parsed with `GenerateTripPlanRequestSchema` before it is sent.
- **Generating** (`PlanGenerating`): „Układam plan podróży…”, a message above an indeterminate coral bar that changes every 4 s (finding places → arranging the days → almost ready) and stays on the last; no percentages. The app waits up to 60 s (`fetch-timeout.ts`); the server stays under ~50 s (Places 10 s + Gemini 40 s).
- **Server** (`generate-trip-plan`, see `backend.md`): owner only (403 otherwise) → one unit of the `trip_plan` quota (3 per user per UTC day) → candidate cities (≤ 3) → one Nearby Search per city → Gemini picks and orders candidates by `placeId` per day and time of day, with a reason; travellers only as `P1…Pn` with interests; output validated against the candidates and the trip dates → saved to `trip_plans` (replacing the previous plan). Any failure after the quota refunds the unit; there is no fallback.
- **Result** (`PlanResult`): „Wygenerowane przez AI”, per day „Dzień N · date · city”, places grouped into morning / afternoon / evening with name, address, the AI reason and „Otwórz w Mapach Google”; a missing place shows „Miejsce niedostępne”. No prices yet. Day blocks fade up 8 dp with a 45 ms stagger (first 6), cross-fade under reduced motion.
- **Generate again:** owner and online only; „Zastąpić obecny plan?” dialog → the cards again.
- **Errors:** daily limit (no retry, names the limit of 3), not enough places (`plan.error.noPlaces`, copy from design-context `ai.error.noPlaces`), offline (`plan.error.offline`, only when the request never reached the server; a 60 s timeout counts as a failure), anything else „Nie udało się ułożyć planu” with „Spróbuj ponownie”, which sends the same request again (D21).
