# AI trip plan

Entry: the "Plan" side of the Plan tab's "Plan" / "Discover" switch, shown only with a current trip (`TripPlanSide` in `src/features/plan/`). Without a current trip the Plan tab is a placeholder ("Plan", "This screen is coming soon."; see [pill-navigation.md](pill-navigation.md)). Needs internet: offline the screen shows the banner, "The plan needs an internet connection." and a disabled "Plan with AI"; a saved plan is not shown offline (its names come from Google at view time).

Plan and decisions: `prompts/ai-trip-plan/plan.md` (D1–D19).

- **Read** (`useTripPlan` → `fetchAppTripPlan` in `src/data/app-trip-plan.ts` → `fetchTripPlan` in `src/data/trip-plan.ts`): `trip_plans` row by trip id (RLS: owner or linked member), parsed with `TripPlanSchema`; none → empty state. Memory-only query, no retry.
  - Names, addresses and Maps links: `usePlaceDetails` → `fetchAppPlaceDetails` (`src/data/app-trip-plan.ts`) → `place-details` Edge Function in chunks of ≤ 40 ids, merged into a map; memory only (Google allows storing only `placeId`, D14). A failed lookup shows an error with retry.
- **Empty:** the owner sees "No trip plan yet" and "Plan with AI" (the button needs the trip's destination to map to an airport, and is disabled offline); a linked friend sees "The organizer hasn't built a plan yet." without a button.
- **Question cards** (`PlanWizard`): "Where do we explore?" ("Only {{city}}" / "Other cities too") → "How far should we look?" 50/100/200/300 km, default 100 (only for other cities) → own cities (optional, ≤ 2, from the airport list, sent as IATA codes; not the destination, no duplicates) → "What kind of plan?" preference chips (optional: relaxed / intense pace — exclusive —, lots of food, no museums). Cards slide (Reanimated `SlideInRight` / `SlideOutLeft`, reversed going back, `motion.duration.emphasis`); with reduced motion they cross-fade in 80 ms. The request is parsed with `GenerateTripPlanRequestSchema` before it is sent.
- **Generating** (`PlanGenerating`): "Building your trip plan…", a message above an indeterminate coral bar that changes every 4 s (finding places → arranging the days → almost ready) and stays on the last; no percentages. The app waits up to 60 s (`fetch-timeout.ts`); the server stays under ~50 s (Places 10 s + Gemini 40 s).
- **Server** (`generate-trip-plan`, see `backend.md`): owner only (403 otherwise) → one unit of the `trip_plan` quota (3 per user per UTC day) → candidate cities (≤ 3) → one Nearby Search per city → Gemini picks and orders candidates by `placeId` per day and time of day, with a reason; travellers only as `P1…Pn` with interests; output validated against the candidates and the trip dates → saved to `trip_plans` (replacing the previous plan). Any failure after the quota refunds the unit (`no_places` is a 422 and `cities_unknown` a 502, both refunded); there is no fallback. A non-owner gets 403 `forbidden`; the client maps `forbidden` and `unauthorized` to the generic error copy.
- **Result** (`PlanResult`): "Generated by AI", per day "Day {{n}} · {{date}} · {{city}}", places grouped into morning / afternoon / evening with name, address, the AI reason (hidden when it mentions a person id) and "Open in Google Maps"; a missing place shows "Place unavailable". No prices yet. Day blocks fade up 8 dp with a 45 ms stagger (first 6), cross-fade under reduced motion.
- **Generate again:** owner and online only; "Replace the current plan?" dialog ("Replace" / "Cancel") → the cards again. The button is "Generate again".
- **Errors:** daily limit (no retry, names the limit of 3), not enough places (`plan.error.noPlaces`, copy from design-context `ai.error.noPlaces`), offline (`plan.error.offline`, only when the request never reached the server; a 60 s timeout counts as a failure), anything else "Couldn't build the plan" with "Try again", which sends the same request again (D21). Every error except the daily limit shows "Try again" plus "Cancel". Copy: offline "Generating a plan requires an internet connection."; not enough places "We couldn't find enough matching places. Change the interests or the day range."
