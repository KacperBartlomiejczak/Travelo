## Shared components / hooks
- `Field` (label + error frame, input border/box/text styles). Optional props:
  - `hint`: shown under the control, hidden while an error shows;
  - `messagesFirst`: puts the hint / error between the label and the control, as in the interests block;
  - The error has a `CircleX` icon (`field-error-icon`) and is a polite live region.
- `TextField`: `hint`, `inputRef`, `editable` (disabled background `surface.secondary`), keyboard and autofill props. `AirportField` (search over the bundled list), `DateTimeField` (`.tsx` iOS wheel in UTC, `.android.tsx` date→time dialogs, `.web.tsx` browser input; shared `DateTimeFieldBase`), `AmountField` (§10.5), `TextButton` (secondary / ghost / destructive — secondary with the `status.error` label; optional `loading`, a spinner in an icon-sized slot), `IconButton` (disabled at `opacity.disabled`), `Stepper` (adjustable for screen readers), `SegmentedControl` (labels on one line, the font shrinks to fit instead of wrapping, D19), `Chip` (checkbox; optional `disabled` at `opacity.disabled`; 32dp tall with a 44dp `hitSlop` — a written exception to design-context §10.6, theme-split D9; the same width selected and unselected: the unselected chip keeps the ✓'s room (icon + gap) in its side padding, so a toggle never reflows the row), `InterestChips` (the 17 interest chips in 6 groups; `selected`, `onChange`, `disabled`; a tap also calls `Keyboard.dismiss()`, D11; used by the wizard's `FriendCard` and the profile setup), `Card`, `StepIndicator` ("Krok 2 z 4" + bar), `LayoverLabel` (`inset` 16dp only between the wizard's segment cards, trip-create-wizard D27; flush with the flight lines on the home screen and the summary, friend-invite D8), `CoverPicker` (required cover: presets or a gallery photo, see below), `TripHero` + `TripHeroSkeleton` (a full-width `SkeletonBlock` of the hero's height, `radii.none`). `SkeletonBlock` (`width`, `height`, optional `radius` and `color`): a placeholder block in `skeleton.base` with the `components.skeleton.radius` default that pulses in opacity 1 → 0.5 → 1 over 1200 ms (`motion.microinteraction.skeletonPulse`, Reanimated), still while reduce motion is on or unknown, cancelled on unmount, hidden from screen readers. `AnimatedSplash` (`ready`, `onDone`): full-screen overlay on the theme canvas playing `assets/animations/splash.json` once with `lottie-react-native`, 280 dp wide (`screenMetrics.splash.animationWidth`) and centered so frame 0 matches the native splash; dark theme → `colorFilters` `t` / `wordmark` → `surface.inverse`, `sun` → `brand.primary`; reduce motion `null` → frame 0 static, `true` → final frame static; after the end, while not `ready`, a `brand.primary` `ActivityIndicator` under the logo (busy, „Ładowanie aplikacji”); when ended + ready it fades out (`motion.duration.standard` / `reduced`) and calls `onDone` once; a Lottie load failure counts as ended.

- `ConfirmDialog` (`src/components/ConfirmDialog.tsx`) — §10.17, pill-nav-and-dialog A1–A4:
  - **Props:** `visible`, `title`, `message`, `confirmLabel`, `cancelLabel`, `destructive?`, `onConfirm`, `onCancel`. The caller passes translated strings.
  - **Shell:** RN `Modal` (`transparent`, `statusBarTranslucent`, `animationType="none"`). The scrim `Pressable` (`overlay.scrim`, labelled „Zamknij”) and Android back call `onCancel`, never `onConfirm`.
  - **Box:** width viewport − 40dp up to `size.maxContentWidth`, `radius.lg`, padding 24dp, `surface.elevated`, `elevation.dialog` (no shadow in dark).
  - **Text:** title Heading 3 (accessibility header), message Body M in `text.secondary`.
  - **Actions:** stacked full width, 16dp apart, confirm on top: a destructive `TextButton` (error colour) when `destructive`, else a `PrimaryButton`; cancel is a secondary `TextButton`.
  - **Motion:** fades over `duration.dialog` (220 ms) with its own opacity animation and unmounts after the fade-out; no animation with reduced motion. `accessibilityViewIsModal` on the box.
  - **Optional (profile-settings):** `children` (wraps the dialog in a `KeyboardAvoidingView`), `confirmDisabled`, `busy` (spinner on confirm; cancel, scrim and back do nothing).
  - **Used by:** the wizard's `LeaveGuard`, `SettingsScreen`, `DeleteAccountDialog`, `ExpenseSheet`.
- `PillNav` (`src/components/PillNav.tsx`) — pill-nav-and-dialog D1–D4, R1:
  - **Props:** `items {key, label, Icon}[]`, `activeKey`, `onSelect(key)`. It is presentational; `NAV_TABS` and the router live in `src/features/nav/` and the tabs layout.
  - **Capsule:** `position: absolute`, `bottom` = safe-area inset + 16dp, width viewport − 32dp up to `size.maxContentWidth`, height `size.navPill` (64), `radius.full`, `colors.nav.background` (white in light mode, ink in dark mode — theme-split D2) with a 1dp `nav.border`, `elevation.floating` (shadow in light only). The wrapper is `pointerEvents="box-none"`.
  - **Items:** `Pressable`s of equal width, each ≥ 44 × 44dp, role `button` with `selected` state and the label as accessibility label. Active: icon 24dp + label in `nav.active` (brand); inactive: icon 20dp in `nav.textInactive`. The pressed state uses `nav.pressed` as background (light `neutral.50` — labels ≥ 4.5:1; dark `dark.border`, theme-split D8), the focus ring is 2dp in `nav.active`. The container has no role and is not `accessible`, so each item is its own screen-reader stop.

## Design rules

### Principles
- **Built for one hand, on the move.** Primary actions sit in the thumb zone. Touch targets ≥ 44pt.
- **Adding an expense takes under 5 seconds.** Quick-add from anywhere (floating button → bottom sheet), category chips, last-used currency preselected.
- **Every screen has four states:** loading, empty, error, and (if relevant) offline.
- **Money is always shown with its currency.** Estimates are prefixed with `~` and shown as ranges.
- Light and dark mode from day one.

### Design system
- Before building any UI, read `context/design-context.md` — the single source of truth for visuals.
- All colors, spacing, radii, and typography come from a single theme file as tokens. No hardcoded colors or magic numbers in components.
- All user-facing text goes through i18n keys (start with Polish and English).

### Key screens
1. **Trips** — list of trips, upcoming first.
2. **Trip overview** — members, flights (with layovers), budget status.
3. **Day plan** — timeline; when the group splits, show parallel lanes with member avatars.
4. **Add expense** — bottom sheet, minimal fields.
5. **Trip summary** — totals, by category, plan vs reality, shareable card.
